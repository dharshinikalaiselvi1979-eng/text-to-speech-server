# Database Schema

This project uses a single Supabase (PostgreSQL) table, `speech_history`, to log every
successful text-to-speech generation. It is written to from
`server/controllers/ttsController.js` after a successful call to
`generateSpeech()` in `server/services/ttsService.js`.

## Table: `speech_history`

| Column        | Type                    | Source                          | Description |
|---------------|-------------------------|----------------------------------|-------------|
| `id`          | integer / uuid (auto)   | Supabase (auto-generated)        | Unique identifier for the row. |
| `text`        | text                    | User input (`req.body.text`)     | The original text exactly as typed/pasted by the user, before any translation. |
| `language`    | text                    | User input (`req.body.language`) | The language requested for the generated speech. |
| `voice`       | text                    | User input (`req.body.voice`)    | The selected voice name. Defaults to the string `"default"` if no voice was provided, so this column is never empty. |
| `audio_url`   | text                    | Generated by `ttsService.js`     | Relative path to the generated MP3, e.g. `/audio/speech-1788854952485.mp3`. |
| `spoken_text` | text (nullable)         | Generated by `ttsService.js`     | The text that was actually converted to audio. If the target voice's language is not English, this is the **translated** version of `text`; if translation fails, it falls back to the original text. For rows inserted before this column existed, the value is `NULL`. |
| `created_at`  | timestamptz (auto)      | Supabase (auto-generated)        | Timestamp of when the row was inserted. |

## Notes

- **`text` vs. `spoken_text`**: `text` is always what the user typed. `spoken_text` is
  what was actually spoken — these differ whenever the selected voice triggers
  auto-translation (see the translation logic in `generateSpeech()`).
- **`spoken_text` may be `NULL`**: this column was added to the table after it was
  originally created (to support the translation feature). Rows inserted before that
  migration do not have a value here — this is expected, not a bug.
- **`audio_url` may point to a deleted file**: generated audio files in
  `server/temp_audio/` are automatically deleted 10 minutes after creation
  (see the `setTimeout` cleanup in `ttsService.js`). The database row is kept as a
  permanent history record, but the linked file will 404 after that window.
- **No migration files**: this table was created directly via the Supabase dashboard,
  not via a checked-in `.sql` migration. If the schema changes again, consider adding
  a `migrations/` folder to keep this document and the live table in sync.
